# 指定 UID 历史回帖回填

## Goal

UID 监控首次运行目前只建立主题和回帖水位，不回溯历史内容。管理员缺少一种低风险方式，将某个已监控用户在指定日期之后的历史回帖补充到本地数据中。

本功能允许管理员输入一个已监控 UID 和开始日期，创建持久化异步回填任务。任务拉取该日期起至任务启动时的目标用户回帖并静默保存，同时保持现有实时监控水位和通知语义不变。

## Behavior

- 管理后台提供“UID 历史回帖回填”入口，要求输入：
  - 一个已存在且未删除的 UID 监控目标；
  - 一个开始日期。
- 开始日期使用 `scheduler.timezone_offset` 解释，时间边界为所选日期当天 `00:00:00`，且包含该时刻。
- 每个任务在创建时固定结束时间。任务只处理发布时间满足以下范围的回帖：
  - `postdate >= 开始日期 00:00:00`；
  - `postdate <= 任务启动时间`。
- 任务遍历该 UID 的用户回复列表，直到确认后续结果均早于开始时间；对范围内候选按现有 UID 采集规则请求详情并再次校验作者 UID。
- 回填保存目标回帖、必要的 partial 主题元数据，以及详情响应中按现有 UID 采集语义保存的上下文；不会因为发现一个 TID 而抓取该主题的完整历史。
- 回填为静默导入：不得为回填内容创建 `post_events`、`post_event_watch_matches` 或 `notification_outbox`，也不得触发任何通知渠道。
- 已存在的主题和帖子复用当前自然键去重。重复运行相同或重叠时间范围不会产生重复帖子。
- 回填不得修改 UID 监控的主题水位、回帖水位、`baseline_completed`、启停状态或正常调度时间。
- 回填作为持久化异步任务执行。创建后管理后台无需保持请求连接，即可查看任务状态和最新进度。
- 管理后台至少展示任务的 UID、开始日期、固定结束时间、状态、已请求页数、已处理候选数、新增帖子数以及失败原因。
- 任务状态至少区分等待、运行、成功和失败。失败时保留已成功保存的数据和错误信息；对相同范围重新提交是安全的。
- 全局同一时间只允许一个等待中或运行中的 UID 历史回填任务。存在活动任务时，新提交应被拒绝并显示明确提示。
- 服务重启后，活动任务及其进度不得丢失；任务可以继续执行或被安全地重新领取，且不能因此重复保存帖子。
- UID 不存在对应的未删除监控、日期格式无效或日期晚于服务时区的当前日期时，后台拒绝创建任务并显示后端错误。

## Constraints

- 本功能仅属于 Rust 服务和 `/admin` 管理后台，不改变 standalone Chromium extension。
- NGA 请求继续经过现有账号凭据、请求节流和重试行为；不得通过历史回填绕过账号级请求限制。
- 该任务由管理员显式触发，不受监控目标免拉取时段限制。
- 回复列表的分页、空体 503 结束条件、候选字段校验和详情作者校验遵循 `NGA_API_CONTRACT.md` 的现有约定。
- 帖子持久化继续使用现有全局自然键：主题按 TID，普通回复和楼中楼按 `(tid, pid)` 去重。
- 持久任务状态必须对进程崩溃和重复 worker 周期安全；同一任务不能被多个 worker 同时有效执行。
- 如需新增持久化结构，SQLite 和 PostgreSQL 必须提供同编号且行为等价的迁移。
- 公共 API、管理后台、README 示例和相关设计文档中的行为说明必须保持一致。

## Out of Scope

- 一次回填全部 UID 监控目标。
- 为未创建 UID 监控的任意用户执行历史抓取。
- 回填目标用户的历史主题。
- 回溯目标回帖所在主题的其他历史楼层或构建完整主题副本。
- 为历史内容补建事件、匹配关系或发送历史通知。
- 用历史回填结果建立、重置或推进实时 UID 监控水位。
- 同时运行多个历史回填任务或提供批量并发配置。

## Acceptance Criteria

- 管理员选择一个现有 UID 监控并输入合法日期后，后台立即创建异步任务，页面可以在请求结束后继续显示其状态与进度。
- 服务时区中恰好位于开始日期 `00:00:00` 的目标 UID 回帖会被保存；更早的回帖不会被保存；任务启动后产生的回帖不属于该任务的固定范围。
- 范围内跨越多个回复列表页面的目标 UID 回帖均会被发现、校验并保存，且不会顺带抓取完整主题历史。
- 回填前后 UID 监控的主题水位、回帖水位、`baseline_completed`、启停状态和正常调度时间完全一致。
- 回填新增帖子后，`post_events`、`post_event_watch_matches` 和 `notification_outbox` 的数量不因该任务增加，通知渠道不会收到历史回帖推送。
- 当回帖已由 TID 监控、UID 实时监控或先前回填保存时，任务不会创建重复帖子；重跑相同范围仍能成功完成。
- 存在等待中或运行中的回填任务时，再次提交返回明确的冲突错误，管理后台展示该错误且不创建第二个活动任务。
- 任务成功时记录最终统计；请求、解析或持久化失败时记录失败状态和可见错误，已保存内容可通过后续重跑安全补齐。
- 服务在任务进行中重启后，任务记录和已提交进度仍然存在，后续执行不会导致重复帖子或并发领取同一任务。
- 不存在对应 UID 监控、日期非法或日期晚于当前服务日期时，API 返回可识别的校验错误，任务不会被创建。
- 使用 fixture 和本地测试数据库覆盖日期边界、跨页发现、静默落库、游标不变、幂等重跑、活动任务互斥及恢复领取；自动化测试不依赖实时 NGA 或现有开发数据库数据。
