2026-09-20，Asia/Shanghai。主 agent 执行真实数据库迁移、资源核验和 HTTP 导出；GPT5.6-SOL、XHIGH subagent 独立核对配置、水位及 ZIP 完整性。验收依据为 [Spec09](../spec/09-data-migration.md)、[Spec12](../spec/12-rust-parity-fixes.md) 和 [Spec13](../spec/13-markdown-rendering.md)。

## 结论

用户要求的三项验证均通过：迁入 Cookie 与飞书配置可用；监控配置、基线和历史水位没有非预期变化；TID、UID 的 Markdown 和含本地资源的 ZIP 导出符合预期。没有发现迁移造成的帖子或已下载资源丢失。

本次是独立数据库演练，没有替换现有 Go 数据库或执行正式上线。没有修改生产代码。大主题导出存在实际耗时：56,946 条帖子生成 Markdown 和 ZIP 各约 160 秒；本次功能验收通过，未进行性能修复。

- 以迁移工具的只读、REPEATABLE READ 事务导出真实 PG 的 30 张表；快照时刻为 `2026-09-20T08:53:55.769038Z`（北京时间 16:53:55）。旧服务容器在只读检查时为 `exited`，本轮没有启停旧服务。
- 使用现有 Go 配置中的同一部署密钥。密码、Cookie、App Secret、通知收件地址只在必要的内存校验中使用，不进入本报告。
- 首次转换后读取旧部署设置，再用同一快照离线重放，显式传入 `-download-enabled`，生成最终的 `migrated-final.db`。两次转换均成功，最终报告 `ready=true`。

- 旧部署为资源下载开启、上限 `104857600` 字节（100 MiB）、`store_raw_payload=false`、时区偏移 `+08:00`；核验服务实际设置分别一致，时区采用 `Asia/Shanghai`。
