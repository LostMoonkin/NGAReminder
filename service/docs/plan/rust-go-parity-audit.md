# Rust / Go 功能与实现差异核验表

核验日期：2026-09-20。Rust 基准为归档的 **v0.1.4 / `7a9c9dd`**；Go 基准为 **`a60889b`**，已包含用户资料页、用户名与特殊 header 的补齐。初始审计未修改业务实现；后续修复见[第 6 节](#6-后续修复记录)。各主表保留原基准的行为对照。

以实际源码和可重复的本地探针为依据，Spec 用于辨认已确认的重构取舍，Git 历史用于检查后期修复。不能仅凭旧 README/CHANGELOG 宣称某行为存在。范围限服务端，不含独立浏览器扩展。

表中“缺口”表示 Rust 有而当前 Go 没有；“行为不同”表示两边都有功能但触发条件或结果不同；“明确取舍”有 Go Spec/计划依据；“已对齐”只针对该行列明的行为，不代表整个模块已证明等价。静态代码结论不等于真实 NGA、飞书或 Bark 联调结果。

## 1. 优先核验项

先核验下面这些会影响采集连续性、登录成功率和日常使用的项目。编号可直接用于后续决定“补齐 / 接受现状 / 再联调”。“已复现”表示本地确认差异存在，**不是已经修复**。

## 5. 核验方法与边界

本次是逐功能源码审计和少量定向验证，不是两端所有输入的形式化等价证明。完整覆盖了 Rust 路由表的 55 个 method/path 组合，并核对 Go 所有 handler 路由、NGA、采集、调度、通知、Bot、续期、内容、资源、导出、配置和迁移的主要实现；共 80 个带编号的功能/内部行为条目，包含不同点与重要已对齐点。

| 验证 | 实际结果 | 边界 |
| --- | --- | --- |
