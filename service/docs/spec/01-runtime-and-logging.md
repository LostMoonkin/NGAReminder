# 阶段 01：运行基础与日志

## 目标

建立能在本机启动的 Go 服务，让后续功能沿用统一配置、SQLite、管理入口和排障方式。
完成后，维护者能从一次请求的日志看到经过的操作，并定位失败原因。

## 行为

- 单个进程提供 HTTP API、`/admin` 管理入口和后续后台任务的运行入口。
- 支持关闭全部后台任务、仅启动 HTTP 管理入口用于迁移核验；不修改持久化的监控/渠道开关，核验时不触发采集、资源下载、通知、Bot 或登录续期。
- 启动配置包含监听地址、SQLite 路径、资源目录、管理员凭据、部署加密密钥和调度时区；提供假值示例及默认值说明。
- 配置文件支持环境变量覆盖；启动时校验配置，失败时给出具体字段和原因，并以非零退出码结束。
- 默认时区为 `Asia/Shanghai`；持久化时间统一为 UTC，管理页展示时区及当前运行设置。
- 创建空 SQLite 数据库并完成当前阶段所需初始化；已有配置和数据在正常重启后保留。
- 管理页支持单管理员登录、退出和错误提示；管理 API 保留 API token 访问方式，未认证访问不能读写业务数据。
- 提供不泄露配置的健康检查，能够区分服务可用与数据库不可访问；暂不建设指标平台。
- 所有 HTTP 请求返回关联 ID。按 AGENTS.md 记录实际经过的各层、数据库和外部请求，默认 info 日志可还原调用关系。
- 启动失败、普通 error 和 panic 都记录完整错误上下文及 stack trace；对用户返回可理解的错误和关联 ID。
- 停止进程时停止接收新任务，释放数据库和网络连接；不引入额外 supervisor 或 worker 服务。

## 约束

- 技术栈、分层、日志字段和错误处理遵守 [服务端规范](../../AGENTS.md)。
- SQLite 使用纯 Go 驱动，整个服务在 `CGO_ENABLED=0` 下构建和运行。
- 当前只建立本阶段需要的配置和数据；后续业务表随各阶段增加。
- 写入 SQLite 的凭据保存为加密值或不可逆校验值，运行密钥独立配置；示例和日志使用假值或脱敏值。
- Go 使用独立数据目录，不能把 Rust 数据库当作可自动升级的新库；旧 PG 数据由 [阶段 09](09-data-migration.md) 的显式迁移工具导入。

## 非目标

- NGA 抓取、通知发送和 Cookie 续期。
- 多管理员、注册、RBAC、SSO 和密钥管理平台。
- PostgreSQL、独立缓存、分布式 tracing 服务和高可用部署。
- 为验证日志而增加生产可访问的故障注入接口。

## 验收标准

- [x] 按说明从空目录启动，能够检查健康状态、登录并退出管理页；重启后配置仍在。
- [x] 错误配置或不可写数据库路径导致明确失败，日志能定位原因且没有真实凭据。
- [x] 未登录的管理请求被拒绝，正确管理员凭据和 API token 可分别访问对应入口。
- [x] 一次实际数据库操作能用关联 ID 串起入口、业务操作和数据库日志，包含结果及耗时。
- [x] 用本地错误或 panic 模拟确认：日志含 cause、函数/文件/行号，响应不泄露内部栈；无需添加永久诊断接口。
- [x] 正常停止并重启可继续运行；Go 格式、编译和 vet 检查通过。

## 验证记录

2026-09-17 完成。运行及配置说明见 [服务端文档](../README.md#本地运行)。

- `gofmt` 无待格式化文件；`CGO_ENABLED=0 go build ./...`、`go vet ./...`、`go test ./...` 均在禁用 CGO 的环境中通过。Linux/amd64 产物确认为静态链接，依赖包没有启用的 CgoFiles。
- 本地 SQLite 测试验证认证、会话撤销与重启保留、数据库不可访问时的 503、健康检查仍为 200，以及 panic 原始栈、调用链和日志脱敏。
- 实际二进制从临时空目录启动，完成 HTTP 登录、设置查询、退出、SIGTERM 停止及重启；环境变量可切换后台模式和时区，原配置文件未被改写。
- 无效密钥、不可写路径均以非零退出码结束，并输出原因和栈；未识别的旧 SQLite 被拒绝，其文件摘要保持不变。全部自测使用临时数据和假凭据。
