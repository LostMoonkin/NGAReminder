# 阶段 02：NGA 账号与 TID 监控

## 目标

让用户通过管理页配置 NGA 账号，并手动采集一个主题。
先完成 Cookie、协议解析、帖子保存和增量采集的闭环，为调度与通知提供基础。

## 行为

- 管理页可保存、替换和校验 NGA Cookie；支持完整 Cookie，以及手动填写 passport UID/CID 的现有用法。
- 凭据校验使用需要登录的用户回复接口，不能以公开用户资料页可访问作为登录有效的依据。
- 页面展示账号可用性和最近校验错误，不回显 Cookie；新凭据校验失败时保留原有凭据。
- 用户可创建、修改、暂停、恢复、删除 TID 监控，并手动运行一次；页面显示配置、当前状态和最近结果。
- 初始化提供“保存全部可访问历史”和“从现在开始”两种模式。两者都建立静默基线，不将既有内容视为新增通知。
- 全量初始化按页保存主楼、普通回复和楼中楼评论；从现在开始只建立当前水位，后续保存新楼层。
- 初始化未完成时不标记基线完成；重复执行可复用已保存内容，成功后进入增量采集。
- 增量采集保存新内容；同一主题、回复或评论不会因重跑重复保存，热门引用不产生另一份帖子。
- 增量不得重新遍历全部历史页面。每轮先读取首页，比较上次成功采集的回复总数与总页数；没有增长且没有到期缺口时只请求首页，有增长时从实际楼层水位所在页读取到本轮末页。
- 远端总数和页数快照与水位一同在整轮成功后提交；旧 Go 数据缺少快照时只从已有水位补查尾部，不重建全量基线。重置基线时同时清空快照。
- 不为发现旧楼层下的新评论扩大历史抓取范围；仅对本轮实际请求到的页面保存符合条件的新评论。到期楼层缺口按阶段 08 定位补偿。
- 保留作者、TID/PID、实际楼层、发帖时间、正文、父子关系、来源链接和资源地址；已有正文暂不追踪编辑或删除。
- “重置基线”保留已保存内容，下次按选择的初始化模式重建基线；删除监控只停止采集，不隐式删除已保存内容。
- NGA HTTP 成功但业务失败不能算抓取成功；待审核只跳过本轮，不存在的主题停止自动采集，凭据无效单独标记认证暂停。
- NGA 数据采集与凭据校验沿用 Rust reqwest 的自动重定向：跟随 301/302/303/307/308，最多 10 次跳转（不含初始请求），按最终响应的 HTTP 状态和业务码判断结果。301/302/303 将 POST 转为 GET，307/308 保留方法和请求体；超过跳转上限明确失败。
- 重定向同源时保留 Cookie；主机、有效端口或协议变化时移除 Cookie、Authorization 等敏感头，即使再跳回原站也不重新附带。Referer 按 reqwest 规则随上一跳更新；每次跳转仍共用账号 120 QPM 限流，日志记录状态码、跳转次数和来源/目标主机，不输出 Cookie 或跳转 query。
- 失败或跳过不推进未完成的游标；运行结果记录开始/结束时间、来源、数量及错误摘要，可从页面关联到日志。
- 采集完成后可在管理页看到已保存帖子列表与纯文本预览；富文本和导出在阶段 07 完成。

## 约束

- 依赖 [阶段 01](01-runtime-and-logging.md)，按 [服务端规范](../../AGENTS.md) 实现。
- 协议字段、业务码、楼中楼关系和自然键参考 [NGA 契约](../../../archive/rust-service/service/docs/NGA_API_CONTRACT.md)；协议接入放在 infrastructure。
- 账号、watch、帖子均持久化到 SQLite；网络失败不能留下已前移但内容未保存的水位。
- 抓取默认串行；历史页面并发按后续 [Spec11](11-thread-page-concurrency.md) 补充，不搬迁 worker 租约。

## 非目标

- UID 监控、自动调度、通知、登录续期和历史楼层缺口补偿。
- 追踪旧帖编辑、删除或抓取不可访问内容。
- 兼容 Rust 数据表和旧 API 的逐字段格式。

## 验收标准

- [x] 有效和无效凭据得到不同结果；公开资料可读但登录失效的样本被正确判为无效。
- [x] 全量初始化保存多页内容且不产生通知；从现在开始不导入旧楼层，随后可保存新回复。
- [x] 重复运行不重复保存帖子；主楼、普通回复、楼中楼和热门引用可用脱敏 fixture 正确区分。
- [x] 一次失败或待审核结果保留原有效水位，基线不会被提前标记完成。
- [x] 管理页可完成创建、运行、暂停、恢复、重置和删除，已保存内容不因删除监控而消失。
- [x] 抓取调用链涵盖 HTTP 入口、业务操作、NGA 请求和 SQLite 写入，日志中没有 Cookie。
- [x] 无增长只请求首页；同页新增及跨页新增只读取水位页到末页；失败重试、重启及旧库升级均不触发历史全页扫描。
- [x] 302 后正常响应继续解析；10 次跳转可成功，第 11 次被拒绝；跨源 Cookie 移除、POST 方法转换、最终认证错误分类和跳转限流均由本地 fixture 验证。

## 实现与验证记录

2026-09-17 完成。操作与 API 说明见 [服务端文档](../README.md#nga-账号与手动采集)。

- 管理页提供账号、监控详情、最近运行和帖子纯文本预览；手动采集返回运行记录后在本进程串行执行，无调度器、任务队列或通知设施。
- 每页保存内容与运行计数，整轮完成才提交水位和基线。失败重跑复用已存内容。原实现为发现旧楼新评论而在每轮增量扫描全部页，该策略已于 2026-09-20 按用户要求移除；当前先检查首页，仅抓新增尾部和到期缺口附近页。
- 脱敏 fixture 与临时 SQLite 验证认证接口、拒绝无效替换、AES-GCM 加密存储、多页初始化、from-now、新评论、去重、HTML 转义、CRUD、认证暂停及恢复、中断与重启，以及 HTTP 来源与采集 trace 的关联。核验模式拒绝所有 NGA 操作。
- `CGO_ENABLED=0 go build ./...`、`go vet ./...`、`go test ./...` 通过；`gofmt` 无待格式化文件，产物为静态链接，SQLite 未启用 CGO。
- 实际二进制使用临时配置和数据完成 HTTP 访问、API token 校验、监控 CRUD、SIGTERM 停止、重启持久化、SQLite 完整性检查和日志脱敏；配置文件保持不变。
- 未访问真实 NGA，也未使用现有账号或生产数据库；真实 Cookie 与主题的网络联调留给局域网验收。
