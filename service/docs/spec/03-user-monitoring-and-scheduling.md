# 阶段 03：UID 监控与统一调度

## 目标

让 TID 和 UID 监控持续运行，并允许用户按自己的使用习惯调整频率或暂停自动拉取。
在管理页明确展示一次运行为什么发生、为什么跳过及抓到了什么。

## 行为

- 管理页可创建、修改、暂停、恢复、重置和删除 UID 监控，并手动运行。
- UID 首次初始化读取主题/回帖列表建立各自水位，不导入历史内容或生成新内容通知。
- 后续保存目标 UID 的新主题与新回帖。主题只保存主楼及必要上下文，回复只保存目标内容，不扩展抓取整条讨论。
- 详情返回后再次核对作者；按 PID 请求的回帖即使返回 `lou=0`，仍按回复身份及其 PID 保存。
- 删除或重置监控保留内容；重置后重新静默建立水位，不将已有内容重新通知。
- TID/UID 共用自动调度、运行入口和结果展示；抓取及游标语义各自保持明确。
- 每个监控可设置基础间隔和按星期、时间段覆盖的间隔；未命中覆盖规则时使用基础间隔，多条命中时按配置顺序取首条。
- 间隔默认 60 秒，可设置 30～86400 秒；配置时拒绝非法时间和间隔。
- 免拉取时段与抓取频率分开配置：开始包含、结束不包含，支持跨午夜；跨午夜规则归属于开始日，使用服务配置时区。
- 自动运行遇到免拉取时段时不访问 NGA，记录正常跳过结果并将下次运行移到连续免拉取区间结束；游标和基线不变。
- 管理页和 Bot 的手动运行绕过免拉取限制，但不能绕过手动暂停、认证暂停或同一 watch 正在运行的限制。
- 记录手动/自动来源、开始/结束时间、新增数量、失败/跳过原因；页面展示最近结果、下次执行时间和当前免拉取状态。
- 凭据失效只暂停使用该账号的监控；凭据修复后只恢复因认证暂停的监控，保持用户手动暂停的选择。
- 同一 watch 同时最多执行一次。进程重启后遗留运行标记为中断，后续从已提交水位重新运行，不补造离线期间的每次定时任务。

## 约束

- 依赖 [阶段 02](02-nga-and-thread-monitoring.md)，复用账号、内容保存与错误日志能力。
- UID 协议参考 [NGA 契约](../../../archive/rust-service/service/docs/NGA_API_CONTRACT.md)；免拉取的业务边界参考 [历史 ADR](../../../archive/rust-service/docs/adr/0001-separate-no-fetch-periods-from-fetch-schedules.md)。
- 无数据、网络错误和登录失效必须能区分，不能用失败响应建立空基线或推进水位。
- 只需进程内调度和互斥，不需要跨进程租约和运行审计平台。

## 非目标

- UID 历史回填、主题缺口补偿和通知投递。
- 跨实例任务抢占、离线期间定时补跑和任意 cron 表达式。

## 验收标准

- [ ] UID 初始化静默完成，后续只保存目标 UID 的新主题/回帖，且不抓取整条讨论。
- [ ] 同一 TID 下两个不同 PID 的回帖即使详情均为 `lou=0`，仍各保存一条回复。
- [ ] 本地固定时间样例覆盖间隔覆盖、跨午夜和区间边界；运行时间与页面配置一致。
- [ ] 免拉取期间自动运行没有 NGA 请求且水位不动；同一未暂停 watch 可手动运行。
- [ ] 重复触发不会并发采集同一 watch；重启后的中断运行可见且可以重新执行。
- [ ] 修复账号后认证暂停恢复、手动暂停保持，运行和后台请求日志均可关联。
