# 阶段 05：飞书机器人

## 目标

在飞书中查询服务状态和操作已有监控，减少日常进入管理页的次数。
建立 Cookie 续期需要的可信私聊入口。

## 行为

- 使用阶段 04 配置的飞书应用，以 SDK 长连接接收消息；管理页可启停 Bot 并查看连接状态及错误。
- Bot 开关和通知投递开关独立；关闭其中之一不改变另一项能力。
- 管理页可生成短时有效、一次性使用的绑定码；管理员私聊发送 `/bind <code>` 建立可信身份，也可在管理页撤销绑定。
- 绑定码默认十分钟过期，不能被重复使用；未绑定用户只能尝试绑定或得到简短使用指引。
- 已绑定管理员可使用 `/help`、`/status`、`/watch list`、`/watch run <watch_id>`。
- `/help` 只列出当前已实现的命令；未知命令、缺少参数、目标不存在均回复清楚的原因。
- `/status` 展示账号、监控、通知和 Bot 摘要，不展示凭据；`/watch list` 展示监控启停状态和最近结果。
- `/watch run` 复用管理页的手动运行规则，明确回复已接受、被拒绝或完成结果，不把“已接受”描述成“执行成功”。
- 默认通过私聊操作；需要群内操作时，管理员可显式允许指定群，群内仅支持查询与监控运行，仍校验发送者绑定。
- 同一飞书消息被重复推送时，不重复执行有副作用的命令；消息 ID 的去重结果在正常重启后仍有效。
- 管理页和 Bot 使用同一业务结果与错误含义，Bot 不直接读写业务数据库或复制采集逻辑。
- 收到消息、命令判断、业务执行和回复发送形成可关联日志；不记录原始绑定码或整段私聊消息。

## 约束

- 依赖 [阶段 04](04-notifications.md)；飞书连接和 API 调用位于 infrastructure，入口解析归 handler，业务归 service。
- 使用 [官方 Go SDK](https://github.com/larksuite/oapi-sdk-go) 提供的事件接入能力，不移植 Rust 社区 SDK 或自行重写协议栈。
- 只有当前应用与管理员绑定，不引入角色表或权限管理框架。
- 命令语义参考 [历史 Bot 设计的命令协议](../../../archive/rust-service/service/docs/BOT_INTERACTION_AND_COOKIE_RENEWAL_DESIGN.md#7-命令协议)，实现以本 Spec 的简化范围为准。

## 非目标

- 通用 Bot 平台、命令注册框架、多平台消息模型和自然语言 Agent。
- Cookie 登录交互；相关命令在阶段 06 加入。
- 完整消息审计、群成员管理和多角色授权体系。

## 验收标准

- [ ] 管理页生成绑定码后可以私聊绑定；过期、重复使用和撤销后的身份被正确拒绝。
- [ ] 四类已实现命令有可理解的回复，监控运行与管理页遵循同一规则。
- [ ] 同一消息重复投递只触发一次监控运行，正常重启后重放仍不重复执行。
- [ ] 未授权群及未绑定发送者不能操作监控，显式允许的群可执行查询和运行。
- [ ] Bot 关闭不影响通知，通知关闭不影响 Bot；连接错误可在页面和日志定位。
- [ ] 一条命令的业务调用和回复发送可通过日志串联，绑定码及原始私聊内容不出现在日志中。
