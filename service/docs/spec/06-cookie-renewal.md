# 阶段 06：Cookie 续期

## 目标

在 Cookie 失效后，通过飞书私聊中的确认和验证码交互恢复 NGA 登录。
保留手动更新 Cookie 的入口，减少日常维护而不扩大自动登录范围。

## 行为

- 管理页可启停续期、配置 NGA 登录名和密码、选择已绑定的管理员，并查看最近续期结果。
- 账号被 NGA 明确判为登录失效时，标记认证暂停并向管理员发出续期确认；网络错误和服务器繁忙不能触发密码登录。
- 管理概览的 NGA 账号区域提供“手动续期”和“续期设置与记录”入口，续期设置页也可手动发起；有效 Cookie 不因手动发起而提前停用，已有活动交互时返回该交互，不重复创建。
- 同一账号同时只有一个活动交互。只有绑定管理员私聊确认后才提交登录凭据，不自动循环尝试密码。
- 支持 `/login status`、`/login confirm <request_id>`、`/login captcha <request_id> <code>` 和 `/login cancel <request_id>`。
- 确认后准备 NGA 登录挑战；需要图形验证码时发送图片，只有图片实际发送成功才提示用户提交答案。
- 管理员提交验证码后继续登录，管理页及私聊展示当前等待步骤或最终结果。
- 候选 Cookie 必须通过需要登录的接口校验，且属于预期 NGA UID，之后才完整替换原 Cookie。
- 成功后恢复因该账号认证失效而暂停的监控，保持手动暂停的监控不变。
- 密码错误、验证码失败、过期或主动取消时保留旧 Cookie，清理临时登录上下文；用户可以重新发起。
- 默认十分钟内未完成的交互过期；重启使未完成交互失效，页面提示重新发起，不尝试恢复验证码或密码提交步骤。
- 遇到短信、手机确认、腾讯验证等当前不支持的挑战，提示手动更新 Cookie 并结束交互。
- 日志记录账号 ID、交互 ID、阶段和结果；密码、验证码、Cookie 及挑战响应中的凭据不进入日志、Bot 回复或普通 API 响应。

## 约束

- 依赖 [阶段 05](05-feishu-bot.md)，复用既有账号校验和手动更新能力。
- NGA 协议细节参考 [历史登录协议记录](../../../archive/rust-service/service/docs/BOT_INTERACTION_AND_COOKIE_RENEWAL_DESIGN.md#93-当前网页登录协议)；用脱敏响应验证，不能假定历史抓包仍覆盖所有情况。
- 凭据按 [服务端规范](../../AGENTS.md) 加密保存，登录网络调用归 infrastructure；交互规则归 service。
- 超时、取消和成功都结束同一个业务交互，不复制 API、Bot、后台任务各自的清理流程。

## 非目标

- 自动识别验证码、绕过挑战、无限登录重试和恢复未完成的登录步骤。
- 群内提交验证码或密码、多管理员审批流程。
- 新建通用会话引擎、工作流引擎或秘密管理平台。

## 验收标准

- [x] 明确认证失败只发起一条确认交互；普通网络失败不提交登录凭据。
- [x] 未确认、未绑定、群聊或已经结束的交互不能提交密码或验证码。
- [x] 图形验证码流程可从确认走到成功；候选 Cookie 验证通过且 UID 匹配才被保存。
- [x] 任一步失败、取消、过期或重启都保留旧 Cookie，不留下可继续使用的旧交互。
- [x] 续期成功仅恢复认证暂停；不支持的挑战能回到手动 Cookie 更新流程。
- [x] 用假凭据检查日志和响应：阶段与错误栈可定位，密码、验证码、Cookie 均不可见。

## 实施与自测记录

已通过临时 SQLite、独立 Cookie jar、RSA 表单与 NGA/飞书 SDK HTTP fixture 核验：明确认证失败触发一次确认，授权与确认门禁、图片实际发送后等待验证码、候选认证及 UID 校验、手动暂停保留，以及密码/图片/候选失败、取消、过期和重启保留旧 Cookie。登录解析使用归档脱敏 fixture，日志及普通响应不暴露假凭据。未使用真实账号进行登录或飞书投递。
