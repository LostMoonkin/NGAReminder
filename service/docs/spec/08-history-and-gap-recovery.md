# 阶段 08：历史回填与楼层补偿

## 目标

补齐两种常用内容缺口：用户主动指定时间范围的历史回帖，以及主题中因审核暂时不可见的楼层。
保持实时监控的游标和通知语义清楚，避免把补历史变成重复通知。

## 行为

- 管理页可为已有 UID 监控提交历史回帖回填，选择起始日期；结束时间固定为任务创建时刻。
- 起始日期按服务配置时区的当天零点解释并包含该时刻；未来日期、缺少 UID 监控等输入给出明确错误。
- 回填只保存目标 UID 在时间范围内的回复及必要上下文，不抓取整个讨论、不纳入该用户历史主题。
- 回填始终静默，不生成收件箱事件或通知，不修改实时监控的水位、基线、启停和调度配置。
- 回填由用户显式发起，不受免拉取时段限制；同一时间只运行一个回填任务，页面展示进度、保存数量和错误。
- 相同或重叠时间范围可以重跑，已保存帖子不重复；按 PID 获取的回复仍需正确识别身份和作者。
- 回填失败或进程重启后标记失败/中断，保留已保存内容；用户可以重新提交相同范围，不要求从原页自动恢复。
- TID 完成基线后的增量采集中，若新跨过的实际楼层号有断层，则记录待补楼层；不根据总回复数推测楼层号。
- 楼层补偿从首次发现起最多持续 120 分钟，默认在第 5、15、35、65、95、120 分钟尝试；同一主题同轮的缺口合并抓取。
- 补偿遵守自动任务的暂停、免拉取和账号有效性限制；错过的尝试不集中补跑，超过期限停止主动重试。
- 恢复的楼层可以低于当前水位，但必须是已记录缺口；保存后按当前作者过滤和渠道规则生成一次事件/通知，不回退实时水位。
- 基线中的旧断层不进入补偿；删除或重置监控后旧缺口不再重试。进程重启后有效缺口仍按原截止时间处理。
- 页面展示回填结果和待补/已恢复/已过期的缺口摘要，不增加独立运维控制台。

## 约束

- 依赖 [阶段 04](04-notifications.md) 和 [阶段 07](07-content-and-export.md)，复用已有采集、内容保存与通知规则。
- 历史行为参考 [UID 回填](../../../archive/rust-service/service/docs/UID_REPLY_HISTORY_BACKFILL_SPEC.md) 和 [楼层补偿](../../../archive/rust-service/service/docs/THREAD_FLOOR_GAP_RECOVERY_SPEC.md)；中断后重跑采用本 Spec 的简化约定。
- 去重依靠既有帖子自然键；失败、跳过和回填都不伪造实时水位。
- 按 [服务端规范](../../AGENTS.md) 在单进程内执行，不引入通用任务框架或跨进程恢复协调。

## 非目标

- 用户历史主题回填、基线旧缺口扫描、不可访问内容恢复和永不停止的重试。
- 回填自动断点续传、多个回填并行和历史通知补发。
- 按旧 Rust 的任务表、租约、worker 状态机逐项移植。

## 验收标准

- [x] 日期边界正确，回填只保存目标回复；实时水位和收件箱/通知数量保持不变。
- [x] 两个同 TID、不同 PID 且详情 `lou=0` 的回复分别保存；重叠范围重跑不增加重复内容。
- [x] 回填失败或重启后能看到中断及已保存数量，重新提交可完成剩余数据收集。
- [x] 用固定楼层样例检测新断层，恢复低于水位的缺口时内容和通知分别只产生一次。
- [x] 基线断层、楼中楼评论和总数变化不会误造缺口；暂停/免拉取期间无自动补偿请求。
- [x] 过期、删除或重置后的缺口停止重试；重启不会重新计算或延长原截止时间。

## 实施与自测记录

已通过临时 SQLite 和 NGA fixture 核验：服务时区日期零点包含、未来与越界回复排除、同 TID 多个 `lou=0` PID 分别保存、重叠回填去重、实时配置和收件箱不变、失败保留已提交内容、单任务互斥、正常停机与异常遗留任务重启中断。

固定楼层样例覆盖基线断层与总数变化不创建缺口、同主题多缺口合并抓取、低水位恢复按当前作者过滤和渠道仅通知一次、暂停/免拉取/认证门禁、错过轮次不集中补跑、120 分钟最后一次尝试与到期停止、重启保留期限、重置和删除清除旧缺口。全量 Go 检查及临时二进制 HTTP 启动/重启、Markdown/ZIP 下载、SQLite 完整性检查已通过；外部服务均使用 fixture，未进行真实账号联调。
