# 阶段 09：Rust PostgreSQL 数据迁移到 Go SQLite

后续行为补充以 [Spec12：Rust 行为对齐与迁移补全](12-rust-parity-fixes.md) 为准。

## 目标

在 Rust 服务停机后，用脚本完整导出 PostgreSQL 数据，并转换为 Go 服务可直接使用的 SQLite 文件。assets 继续挂载原目录，不迁移资源文件。
用户保留已采集内容和监控进度，完成核验后由阶段 10 启用 Go 服务，正常运行不再依赖 PostgreSQL。

## 行为

正式切换顺序为 **Rust server 停机 → PG 迁移 SQLite → 核验 → Go 服务上线**。

1. 停机前准备好 Go 可运行制品、迁移命令/脚本和中文操作说明，并在旧数据副本上完成一次演练。开发阶段顺序不表示要停机等待后续开发。
2. 正式迁移时停止 Rust HTTP、采集、通知和 Bot 等全部应用进程，确认不再写入旧库或资源目录；PostgreSQL 保持可读取。
3. 在停止写入后保留 PG 最终备份及部署配置，单独保管旧凭据加密密钥；演练数据不能替代最终快照。原 assets 挂载目录保留。
4. 脚本先完整导出冻结 PG 的应用 schema，再转换为新的 SQLite，输出数量、映射与核验报告；也支持从已导出的快照离线重放。迁移不修改源数据库，也不读取、复制、重命名或删除 assets。
5. 核验通过后，先以后台任务关闭的方式启动 Go 检查管理页和导出，再按阶段 10 启用正常运行；Rust 保持停止，两端不同时处理业务。

迁移按业务含义映射到阶段 01～08 的 Go 数据模型，不直接照搬 Rust 表结构：

| 数据 | 迁移后的要求 |
| --- | --- |
| NGA 账号、Cookie、续期设置 | 保留已配置内容、账号状态和必要关联；用旧密钥解密后按 Go 格式加密，不能把解密失败当作空凭据 |
| 监控及进度 | 保留 TID/UID、名称、启停及暂停原因、频率、时间规则、初始化模式、基线和已提交水位；已删除监控不重新启用 |
| 帖子与资源 | 保留主题、回复、评论、正文、作者、时间、楼层、父子关系、资源元数据和原相对路径；TID/UID/PID 不变，内部 ID 如变化需同步关联。Go 支持读取原分层资源路径，文件不搬迁 |
| 通知与 Bot 配置 | 保留 Bark/飞书配置、接收目标、开关、作者过滤、渠道关联和符合新规则的管理员绑定及授权群；不得将旧低权限绑定自动提升为管理员 |
| 收件箱与投递结果 | 保留事件、已读状态、来源关系和每渠道投递结果/去重依据；已发送内容不重发，旧未发送或发送中记录转为需手动重试的失败记录，并注明迁移原因 |
| 运行、回填与缺口 | 保留用户可见结果摘要和已保存内容；未完成运行/回填标记中断，待补楼层沿用原发现时间与截止时间，不重新延长有效期 |
| 临时状态 | 租约、连接状态、登录交互、验证码上下文、一次性绑定码和待执行 Bot 回复不恢复；已处理 Bot 消息的去重标识保留，防止旧命令重放 |

- 部署文件中的时区、资源下载开关等有效设置也纳入映射说明，不能只复制数据库后套用新默认值。
- 多个飞书应用、无法映射的绑定或其他超出新模型的业务配置必须报告并在正式迁移前处理，不能静默丢弃或任意选择。
- 资源路径保留不等于文件已核验。迁移报告明确未检查 assets 文件；Go 挂载原目录后通过资源扫描检查缺失项，导出时缺失资源仍回退远程链接。
- 迁移本身不访问 NGA、发送通知、执行 Bot 命令或触发登录；迁入的历史帖子不重新创建事件，不重建已经完成的基线。
- 提供可重复执行的迁移命令/脚本，明确输入源、旧/新密钥、目标文件和结果报告；拒绝覆盖已有目标文件，不要求 assets 所在目录为空。
- 中途失败以非零退出码结束，保留明确错误且不发布未完成的 SQLite；使用同一快照向新文件重跑，可得到相同业务数据，不要求断点续传。
- 报告按业务数据列出源数量、目标数量、ID 映射、转换/未迁移项、关联检查和凭据校验结果；诊断明细、未知表或旧专用字段完整保留在 PG 数据快照中，并明确其未进入 Go 模型；凭据不进入报告。
- SQLite 完整性、自然键去重、业务关联、时间与水位、凭据解密的必要检查失败时，不能通过数据迁移验收。
- 启用 Go 正常运行前失败，可停止 Go 并从保留的原库/备份恢复 Rust。Go 已产生新数据后不直接以旧 PG 覆盖或替代新数据；本阶段不提供反向同步。

## 约束

- 依赖阶段 01～08 的数据模型和功能可用；迁移目标必须能由 Go 直接读取、继续采集和导出。
- PostgreSQL 仅作为离线迁移来源，相关依赖局限在迁移工具；Go 正常启动、运行和备份只依赖 SQLite。
- 接受停机迁移与人工核验，交付一次迁移所需的简单工具和文档，不建立通用迁移平台。
- 不启用 CGO；使用当前 Go SQLite schema 和加密实现，一次性 PG 驱动隔离在迁移工具 module 中。
- 对照 [旧 PG schema](../../../archive/rust-service/service/migrations/postgres/)、[凭据加密实现](../../../archive/rust-service/service/src/crypto.rs) 和 [备份说明](../../../archive/rust-service/service/docs/OPERATIONS.md#postgresql-备份与恢复)；按实际源库版本校验后再导入。
- 日志和错误遵守 [服务端规范](../../AGENTS.md)，使用迁移关联 ID、阶段、数量和错误栈排障，禁止输出密钥、连接密码或解密后的凭据。

## 非目标

- 在线迁移、双写、CDC、零停机切换、多版本通用转换或 PostgreSQL 运行时支持。
- 逐表保留旧 worker/审计结构、恢复未完成登录步骤、自动补发旧通知和静默修正无法判定的历史坏数据。
- 任意已有 SQLite 数据合并、自动反向迁移、删除旧环境或迁移后重新从 NGA 抓取全部历史。
- assets 文件迁移、复制、重命名或切换到新资源目录。
- 本阶段 Spec 不提前固定尚未实现的 Go 表结构，也不拆 tickets。

## 验收标准

- [x] 在含 TID/UID 监控、帖子、评论、资源元数据、通知和假凭据的真实 PG 测试库上完整导出并转换；全程不修改源数据、不调用外部业务服务。
- [x] 数据数量与转换报告可核对，SQLite 完整性、自然键及关联检查通过；中文正文、时间、评论关系和原分层路径的本地资源可在 Go 中读取并导出。
- [x] Go 能解密迁入的 Cookie、续期凭据与渠道配置；错误密钥或不支持的配置使迁移失败并给出可处理原因，日志无明文凭据。
- [x] 同一快照向两个新文件重复迁移得到相同业务数据；已有目标被拒绝，不完整快照不能发布 SQLite。
- [x] 基线、水位、启停、暂停及免拉取规则按映射保留；本地 TID/UID 增量样例从原水位继续，不重新建立基线、重复保存历史内容或重发已投递通知。
- [x] 收件箱已读状态及投递结果保留；旧未完成投递等待手动处理，旧登录/绑定码失效，缺口截止时间不延长，旧 Bot 消息不重复执行。
- [x] 提供“停止 Rust 写入 → 最终快照 → 迁移与核验 → 启动 Go 检查”的中文操作说明与回退边界；测试原 PG 和模拟 assets 保持完整。
- [x] 工具交付后可进入 [阶段 10](10-single-host-delivery.md)；Go 读取迁入文件无需 PG。实际旧库迁移和正式上线在部署时执行。
