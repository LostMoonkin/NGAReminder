# 阶段 10：单机交付与上线

## 目标

把已完成的 Go 功能交付为自己能部署、升级和恢复的服务。
提供一套简短中文操作说明，在数据迁移核验通过后启用 Go，结束对旧 Rust 服务运行环境的依赖。

## 行为

- 提供从源码构建和启动的命令，以及使用同一入口运行的容器配置；单个进程承担 HTTP、调度和 Bot。
- 容器只需配置文件/环境变量及持久化数据目录，不依赖 PostgreSQL、Redis 或额外 worker。
- 配置示例使用假值，列出启动所需配置及 NGA、Bark、飞书的最短接入步骤。
- 中文服务端文档从 [docs/README.md](../README.md) 进入，说明启动、停止、健康检查、日志关联 ID、常见配置错误和数据目录内容。
- 文档说明首次配置账号、建立监控、绑定 Bot、续期及导出的实际操作，链接对应页面和 API 示例。
- 现有 Rust 部署按 [阶段 09](09-data-migration.md) 完成停机迁移和核验，再使用迁入的 SQLite、资源及配置上线；先核验管理页，再开启后台任务、通知和 Bot，Rust 保持停止。
- Go 制品、启动配置和所需发布准备在正式停机前完成；新用户可从空库部署，已有用户不得以空库启动替代迁移验收。
- Go 服务端具有独立版本与发布标签；恢复服务端构建/发布入口时构建 Go，扩展继续沿用自己的版本和工作流。
- 日志输出交给容器或宿主进程管理，说明查看和保留方式，不建设独立日志平台。
- 备份采用停止服务后复制 SQLite、资源目录与配置的简单步骤；另行安全保管部署加密密钥，避免出现有数据库却无法解密的备份。
- 恢复到空数据目录后，账号配置、监控、已存内容和资源可继续使用；恢复期间不要求服务持续在线。
- 升级前保留程序/镜像版本和数据备份；如涉及不兼容数据变更，按文档恢复匹配版本及数据，不要求任意版本降级。
- Rust 归档和旧数据继续保留，Go 部署使用自己的路径；发布或首次启动不能清空、升级旧库。

## 约束

- 正式上线依赖阶段 01～09 完成；制品与部署说明可提前准备，各阶段以其自身验收为准，不在这里重复扩大功能范围。
- 部署遵守 [服务端规范](../../AGENTS.md)，仅提供 SQLite 单机方案。
- 构建与发布设置 `CGO_ENABLED=0`，运行环境不需要系统 SQLite 或 C 运行时依赖。
- 数据库与资源共同备份；凭据密钥不能提交到仓库或写进镜像。
- 实际构建命令、容器依赖和发布规则随最终 Go 工程记录，不复制 Rust 的构建链。

## 非目标

- 零停机升级、自动回滚、跨实例容灾、多架构发布矩阵和性能基准平台。
- 重复实现阶段 09 的迁移工具、旧 API 兼容代理或清理旧环境。
- 扩展发布改造、托管服务和商业化运维能力。

## 验收标准

- [ ] 按中文文档可从空目录启动二进制和容器，使用相同功能且仅需 SQLite。
- [ ] 现有部署使用迁移验收通过的数据上线，原监控进度和已存内容可用；Rust 未重启，Go 运行无需 PG 连接。
- [ ] 停止并重启后监控配置、内容和资源保留，日志可定位一次后台采集与通知。
- [ ] 在临时目录完成一次停机备份与恢复，恢复后能够读取内容、解密凭据并导出本地资源。
- [ ] 用已完成阶段做一次手工流程核验：配置账号、监控、通知、Bot、续期及导出，无需新增完整端到端测试框架。
- [ ] 服务端构建/发布配置只指向 Go，扩展发布检查和版本独立性保持。
- [ ] 文档链接与配置示例有效，必要的 Go 检查通过，仓库不包含运行数据或真实凭据。
