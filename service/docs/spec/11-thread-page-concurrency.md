# 帖子页面并发抓取

## 目标

恢复大帖全量初始化时的页面并发能力，让用户在管理页设置并发数。不同 TID/UID 监控可以同时运行，避免一个大帖阻塞其他监控。

## 行为

- TID 新建及配置页提供“历史页面并发数”，范围 1～16；默认 1 表示串行。设置保存到 SQLite，API 返回当前值，重启后保留。
- 该设置只用于“保存全部可访问历史”的初始化及重置后重新初始化。修改并发数不重置水位；从现在开始、增量采集、UID 列表/详情和楼层补偿继续按现有规则逐页处理。
- 先读第一页确定本轮页数，再按配置并发抓取后续页面；在途页面请求不超过设置值，不追赶本轮开始后增长的尾页。
- 共用 NGA 账号的所有抓取和凭据校验请求合计限制为 120 QPM，按至少 500ms 的启动间隔平滑发送。等待响应不占用其他请求的启动机会，限流等待可随任务取消结束。
- 不设置不同 TID/UID 监控的并发上限；手动、Bot 与自动调度共用此行为。同一 watch 不重复执行，运行中的 watch 修改/重置/删除仍返回忙碌提示；其他 watch 可以运行和修改。
- UID 历史回填仍同时最多一个，只与同一 UID 监控互斥，不阻塞其他监控。账号替换和资源清理仍需等待现有采集结束，避免覆盖凭据或删除正在引用的资源。
- 页面按页序保存并展示已完成页数和新增条数；任一页面失败或停机时取消未完成请求，保留已提交内容，不推进未完成基线/水位。重跑去重，全量初始化保持静默。
- 并行运行中的认证失败仍暂停该账号的监控；其他成功运行不能清除认证暂停。
- 已有 Go 数据库的监控默认并发数为 1；PG 迁移时保留旧 TID 已启用的历史并发数，未启用的转为 1。

## 约束

- 遵守 [服务端规范](../../AGENTS.md)，不启用 CGO，保持 Gin/GORM/SQLite 与现有日志调用链。
- 本 Spec 替代 [阶段 02](02-nga-and-thread-monitoring.md) 中不搬迁并行参数及 [阶段 03](03-user-monitoring-and-scheduling.md) 的全局串行限制；保留单 watch 互斥、免拉取和事务边界。
- 内存随并发数有界，不把整个大帖的响应全部缓存在内存后才写库。

## 非目标

- 不同监控的并发配置、worker 队列、跨进程协调和动态吞吐调优。
- 图片下载并发、UID 内部并发、自动续传和新的重试机制。

## 验收标准

- [x] 页面/API 可创建、修改和回显 1～16 的并发数；非法输入拒绝，省略字段保留旧值，新库/旧库/重启行为正确。
- [x] 慢响应的多页 fixture 出现实质并发且不超过配置值；与串行结果一致，无遗漏、重复内容或基线通知。
- [x] 多个监控同时运行且请求合计遵守 120 QPM；同一监控的重复手动/自动触发被拦截。
- [x] 页失败、取消及重启不误提交水位，重跑可完成；并行成功不覆盖另一个任务造成的认证暂停。
- [x] PG 导入保留启用的历史并发配置，未启用时为 1；Go build、vet、相关测试及全套测试在 CGO 关闭下通过。
