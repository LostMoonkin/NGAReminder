# Spec12：Rust 行为对齐与迁移补全

## 目标

落实用户在 [Rust / Go 核验表](../plan/rust-go-parity-audit.md) 中选定的 14 项差异，恢复 Rust v0.1.4 的可观察行为，并核验旧 PG 导入和已有 Go SQLite 升级是否遗漏数据。

本次实现前的代码基准为 `2034a57d45f759983a43101f333acb95e2e890a8`。历史实现从 [归档索引](../../../archive/rust-service/ARCHIVE.md) 查询；不复刻 Rust 的内部架构。

## 行为

| 编号 | 对齐后的行为 |
| --- | --- |
| C02 | UID 候选主题/回复详情不存在时，本轮失败并保留两份水位，UID 监控继续按计划重试；不能因一个帖子不存在而停用整个用户。已有 Go 库中能由旧运行记录证明的同类误停可恢复调度，保留原水位和手动暂停。 |
| C03 | 资料页缺少用户对象或返回 UID 不符时，标记用户不存在并停止自动采集；网络、JSON 格式等临时错误仍可重试。 |
| C04 | 下次执行时间取当前间隔与下一覆盖规则边界的较早者；沿用配置时区、首条规则优先、跨日归属和免拉取规则。 |
| N01 | 登录公钥支持 NGA 页面 JavaScript 字符串中的转义换行与续行，规范化后解析 RSA PEM。 |
| N03 | 有效账号首次进入认证失效时，独立建立系统告警，向全部启用的 Bark/飞书渠道排队发送；无需开启续期，重复失败不重复建告警。恢复有效后关闭告警，历史和失败重试可查询。 |
| N05 | TID 新回复通知采用已保存的主题标题，主题标题确实未知时才回退到 TID。 |
| N06 | 匹配 UID 监控的通知采用“用户监控：昵称”（未知则 UID），正文包含作者、楼层、摘要和原帖链接；与 TID 同时命中时仍合并内容事件。 |
| N08 | 管理页和管理 API 可以取消活动续期、测试已保存续期配置。取消幂等且清除登录上下文；测试验证配置和当前管理员私聊绑定，并探测 NGA 登录公钥和验证码协议；不提交账号密码、不发送 Bot 消息、不修改 Cookie。 |
| D01 | 提供用户汇总 API 和管理页，列出 UID 监控的昵称、已保存帖子数、涉及主题数和最新发布时间，包含零内容及手动暂停的监控。 |
| D02 | 独立保存主题标题、版面、作者、覆盖范围、远端分页统计和最后观察时间；仅采到用户回复也保存局部主题，局部观察不覆盖已知完整信息，无帖主题仍可浏览汇总。 |
| D09 | 帖子保存实际响应页码；管理页原帖链接使用 `tid&page#pid…Anchor`，未知页码回退原有链接。通知继续使用 Rust 最终版本的 `tid&pid`。 |
| D10 | 资源下载允许 Rust 的六个 HTTPS 图片域名；飞书图片上传沿用自己的三个域名，不混用两种范围。 |
| D11 | 资源支持音视频及任意附件类型，默认上限 10 MiB，可配置；检查声明长度及实际读取长度、接受成功的 2xx、禁止跳转。优先使用安全的原始扩展名，否则按 MIME 或 `.bin` 落盘。 |
| D16 | 提供默认关闭的 raw payload 保存配置；启用后保存每个主楼、回复和评论的原始 JSON，包括未识别字段。迁移保留旧 raw，不受新采集开关影响。 |

六个资源域名：`img.nga.cn`、`img.nga.178.com`、`img4.nga.178.com`、`img6.nga.cn`、`img7.nga.cn`、`img8.nga.cn`。

## 约束

- 维持现有 Go 分层、单进程、SQLite、无 CGO 和凭据加密要求；网络访问不占数据库事务。
- **任何主题增量都不能重拉全量历史**。Spec11 只影响首次或重置后的全量初始化并发；本次修复不得扩大增量和缺口补偿的请求范围。
- UID 增量必须在全部列表和详情成功后一起提交内容、水位、通知；失败不推进水位。
- 不覆盖已保存正文，不因新增元数据删除帖子、监控、事件、投递或资源；旧 Go 数据只能回填可推导的信息，未知页码、原始 JSON 不伪造。
- 旧 PG 仍作为只读来源；保留完整导出快照和原 assets 挂载，迁移失败不发布不完整的目标库。
- 旧主题（包括无帖子主题）、分页、raw、告警及投递历史需进入可用模型或有明确可核验的历史映射，不能只因旧转换器未使用而遗漏。
- 修复完成后专门 review 数据迁移：对照 Rust 表和字段、转换映射、目标模型、关联关系和验证器，并记录实际运行的检查及限制。

## 非目标

- 不实施核验表其余未选定差异，不恢复 PG 运行时、多实例或旧 API 的逐字段兼容。
- 不回抓远端历史以补齐旧 Go 库从未保存的信息，不迁移资源文件本体。
- 不发布或切换真实服务，不修改 Rust 归档及浏览器扩展。

## 验收

1. 使用本地 fixture 验证 UID 候选不存在可重试、用户不存在停止、两者水位均不前移；现有增量请求页码回归继续通过。
2. 验证规则开始、结束和跨午夜边界；长基础间隔不能越过下一规则开始。
3. 使用真实形状的转义 RSA PEM 登录页面验证登录准备，非法公钥仍明确报错。
4. 认证失效在续期关闭时仍产生一次告警及各启用渠道投递；重试/重启不重复创建，恢复后关闭，下一次失效可重新告警。
5. 通知验证 TID 标题、UID 昵称与楼层；Web 验证取消/配置测试入口及零内容用户汇总。
6. 验证仅回复主题、无帖主题、完整/局部信息合并、页码锚点与通知链接区别，以及原始 JSON 开关和评论 raw。
7. 资源验证新增域名、音视频、7z/未知 MIME、安全扩展名、配置上限及超限/跳转失败。
8. 迁移 fixture 覆盖主题/页码/raw/系统告警和关联投递，并核对计数、自然键和历史；已有 Go 库升级不丢内容与水位。旧 `deliveries.event_id/channel_id` 没有默认值时也能完成升级和重启，保留投递记录；升级失败时表结构、索引及数据整体回滚。
9. 完成主模块与独立迁移模块的格式、build、vet、相关测试，以及文档链接和 `git diff --check`；未实际执行的真实库切换不声称通过。

## 升级阻塞修复

2026-09-20：旧 Go 数据库启动停在新增 `deliveries.alert_id` 后。补齐已有列默认值需要重建表，SQLite 驱动在升级事务中重新申请连接，导致单连接池等待自身。迁移改为复用当前事务连接，继续保留整个升级的提交/回滚边界。

[升级回归测试](../../internal/repository/upgrade_test.go) 使用旧表结构和假投递记录，覆盖默认值升级、数据保留、重复启动，以及后续唯一索引失败时的整体回滚。原有用例从新表删除字段，遗漏了旧列无默认值的情况；新增用例在修复前能稳定复现超时。

只读提取现有旧库表结构，在临时库写入假数据后运行实际二进制，首次升级和再次启动均完成监听、`/healthz` 返回 200、SIGTERM 正常退出，投递记录保持一致。
