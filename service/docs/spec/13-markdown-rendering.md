# Spec13：基于 ngapost2md 的 Markdown 渲染

## 目标

当前 Markdown 导出只覆盖基础 BBCode，无法完整表达 NGA 正文中的表情、匿名名、骰子、音视频和带作者、时间的引用关系。

在 service 内复刻 ngapost2md 的 Markdown 渲染规则，替代现有 Markdown 转换。用户仍从现有 TID/UID 入口导出已保存内容，普通 Markdown 与 ZIP 内的 `content.md` 使用同一套新规则。

## 行为

- 导出范围和入口沿用现状：TID 导出该主题已保存的内容；UID 仅导出目标用户已保存的帖子，并按 TID 分组。正文来自已保存的 `Body`，不依赖可选的 raw payload。
- 保留现有文档的主题分组、标题层级、作者、UID/PID、发帖时间、楼层/父帖关系和原帖链接；时间格式与未知值回退沿用现状。复刻范围为正文渲染及引用跳转，不要求整份文件与上游模板逐字一致。
- 主楼、普通回复和楼中楼评论采用相同的正文规则，兼容当前存量 BBCode 与 NGA app_api 返回的混合标记。

| 内容 | 导出行为 |
| --- | --- |
| 换行与转义 | 按上游识别的换行、实体及字面量 Unicode 转义恢复可读内容，保留段落；代码块内部按原文展示，不转换其中的论坛标记。 |
| 基础格式 | 保留现有强调、删除线、普通引用、代码块和链接能力；识别 app_api 对应的 HTML 形式，不能将正常格式标签直接展示为转义源码。 |
| 表情 | 复刻上游表情映射，以 Markdown 图片引用对应的在线表情；未知表情保留原文。 |
| 匿名名 | 接口已返回的可读 `author.username` 直接保留，包括 `author.uid = -1` 的帖子；仅将作者名或正文中仍出现的有效 `#anony_…` 按上游规则转换，转换结果沿用上游的 `?` 后缀。无需读取 `author.annoy` 或 raw payload；异常编码保留可读原文，不中断导出。 |
| 骰子 | 将 NGA 骰子结果呈现为上游风格的 ROLL 文本，保留投掷表达式和结果。 |
| 折叠 | 将上游支持的折叠 HTML 与现有 `[collapse]` 内容输出为 `<details>` / `<summary>`，保留标题、正文和换行。 |
| 引用与回复 | 识别带 TID/PID、作者、UID 和时间的 NGA quote / Reply to 标记，按上游语义输出引用块及跳转链接；保留多行和嵌套引用内容，普通 `[quote]` 继续可读。 |
| 图片 | 输出 Markdown 图片；相对附件地址及 `.medium.jpg` 按上游规则归一化，优先使用已有资源映射，保留图片出现顺序。 |
| 音视频 | 识别上游支持的 app_api 音视频 HTML 及现有音视频 BBCode，输出带“音频”或“视频”标识的资源地址，沿用上游的文本呈现语义。 |
| 未知内容 | 未识别或不完整的标记保留可读文本，不丢弃正文，也不导致整个导出失败。 |

- 引用目标在本次导出中时跳转到对应楼层或评论；锚点在整份文档内唯一，UID 跨主题导出时不同主楼的 PID 0 不冲突。目标不在本次导出中时使用可确定的原帖链接；无法确定链接时保留引用文字。
- 不启用上游的原文补全：只展示正文中已有的引用内容，不为回复追加其他帖子的正文，不因引用或媒体联网请求 NGA、用户资料或资源。
- 普通 Markdown 使用远程资源地址。ZIP 中已下载且可读的相关资源继续使用包内相对路径，缺失资源回退远程地址；图片地址归一化不能破坏已有资源匹配。表情默认引用在线地址，不增加表情下载流程。
- ZIP 的 `content.md`、`metadata.json`、资源去重、其他附件链接、分批导出和临时文件清理规则保持现状；同一批内容的两种导出只因资源路径产生必要差异。
- 保留现有文本和链接安全处理：正文中的脚本、事件属性和危险协议不得成为可执行输出；折叠与锚点只输出受控 HTML，不直接透传任意 NGA HTML。

## 约束

- 参考基准固定为 ngapost2md `neo` 分支提交 [`e3b94346c805ac851ce2584e5ab4e3735846a3c9`](https://github.com/ludoux/ngapost2md/tree/e3b94346c805ac851ce2584e5ab4e3735846a3c9)，以后上游变化不自动改变本 Spec。
- 以该提交的 [nga.go](https://github.com/ludoux/ngapost2md/blob/e3b94346c805ac851ce2584e5ab4e3735846a3c9/nga/nga.go) 中 `fixMost`、`fixContent`、`processMedia` 的渲染部分，以及 [utils.go](https://github.com/ludoux/ngapost2md/blob/e3b94346c805ac851ce2584e5ab4e3735846a3c9/nga/utils.go) 中表情映射、匿名名转换为依据；`genMarkdown` 仅参考引用锚点语义。网络、文件下载及配置副作用不在复刻范围。
- 在本项目内实现或移植必要的渲染代码；不通过 `go.mod`、嵌套模块、submodule、CLI 或外部服务依赖整个 ngapost2md。复制或改写其代码、映射表时记录来源提交并保留 [MIT 许可证及版权声明](https://github.com/ludoux/ngapost2md/blob/e3b94346c805ac851ce2584e5ab4e3735846a3c9/LICENSE)。
- 本 Spec 的兼容和资源规则优先于上游行为；不复刻会导致内容丢失、无效跳转或不安全输出的缺陷，也不减少现有基础格式支持。
- 本 Spec 更新 [阶段 07](07-content-and-export.md) 的 Markdown 转换要求；共享规则约束不要求 Web 和通知同步采用上游渲染，二者现有可观察行为保持不变。[Spec12](12-rust-parity-fixes.md) 的资源规则继续有效。
- 遵守 [服务端规范](../../AGENTS.md)。不改写已保存正文、作者或资源记录，不新增数据迁移；导出保持分批读取，不将完整主题及资源二进制全部载入内存。

## 非目标

- 引入上游爬虫、账号/Cookie、请求并发、配置文件、调度器或 Server 模式。
- 复刻上游整份文档模板、热门回复榜、点赞数、IP 属地、文件切分和增量追加文件机制。
- 补抓引用原文、补下载媒体、修改资源采集范围或迁移既有资源文件。
- 扩展 Web 富文本、通知摘要、浏览器扩展的格式支持，或增加 Markdown 渲染器切换配置。

## 验收标准

- [x] 使用少量本地 fixture 验证上表转换：覆盖真实形状的 app_api 正文及现有 BBCode，包含表情、匿名、骰子、折叠、音视频、多行/嵌套引用；与固定上游版本的预期语义核对，本 Spec 明确的适配差异单独断言。
- [x] 现有强调、代码块、普通引用和链接仍可读；代码块中的论坛标记保持原样，未知/不完整标记不丢正文，脚本和危险链接不会成为可执行输出。
- [x] TID 与跨主题 UID 样例内容完整、顺序稳定，UID 不混入其他作者；主楼、回复、评论的引用跳转正确，跨批次目标可定位，未导出目标不产生无效的文内跳转。
- [x] Markdown 与 ZIP 使用相同正文规则；ZIP 图片、音视频及其他附件能定位到已打包资源，归一化图片仍能匹配本地文件，共享资源只打包一次，缺失资源保留远程地址。
- [x] 关闭网络访问和 raw payload 保存后，已有内容仍能完成导出；导出不修改数据库或下载资源，完成与取消后的临时文件清理继续通过现有检查。
- [x] Web 富文本与通知摘要现有回归通过；在 `CGO_ENABLED=0` 下完成格式检查、build、vet 和相关及全套测试，文档相对链接与 `git diff --check` 通过。
