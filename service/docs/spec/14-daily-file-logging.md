# Spec14：日志文件、按日切分与 SQL 分流

## Goal

服务自行将运行日志保存到本地文件，方便直接查阅和备份，不依赖 Docker `json-file` 或 shell 重定向。
将 SQL 日志单独保存，减少终端输出，同时保留查询失败时的排障信息。

## Behavior

- 新增启动配置 `logs_path`，默认 `data/logs`；支持环境变量 `NGA_REMINDER_LOGS_PATH` 覆盖。
- 相对日志路径以配置文件目录为基准；没有配置文件时以进程工作目录为基准。管理页和配置 API 展示实际日志目录。
- 有效配置加载后自动创建日志目录，并直接追加写入文件；同一天重启不覆盖已有日志。
- 普通日志同时输出到 stdout 和 `app-YYYY-MM-DD.log`，包括业务流程、HTTP 请求、启动与停止信息。
- SQL 日志写入 `sql-YYYY-MM-DD.log`，不混入普通日志文件；非 error SQL 不输出到 stdio。
- SQL 查询真正失败时以 error 级别同时写入 SQL 文件和终端，保留参数化语句、耗时、行数、原因、堆栈和调用链；正常的“未找到记录”不升级为 error。
- SQL 错误记录与业务边界错误可通过同一 trace 关联；业务边界原有的错误记录仍只打印一次。
- 终端和两类文件均使用无颜色的传统文本格式：时间、级别、消息及 `key=value` 字段，沿用现有脱敏规则。
- 文件日期和文本时间使用配置的 `timezone`；跨过本地午夜后，下一条日志自动写入新日期文件，不需要重启。
- 两类文件保留今天及之前 29 个自然日。启动及日期切换时清理更早的本服务日志；不删除目录内其他文件、目录或符号链接。
- 无法创建日志目录或打开当日日志时启动失败并在终端给出原因。运行期间写入、切分或清理失败须在 stdio 可见，不能静默丢弃。
- 正常退出前写入停止日志并关闭文件。容器继续挂载 data 目录即可持久化默认日志。

## Constraints

- 沿用 zerolog、既有 trace/span 字段、错误堆栈和脱敏约定；SQL 不输出绑定参数。
- 保留后台空轮询检查静默的行为。
- 配置优先级沿用环境变量高于 JSON 文件，配置修改在重启后生效。
- 保留 30 天为固定行为，不增加保留时间或日志格式配置。
- 支持现有单机单进程、`CGO_ENABLED=0` 部署。

## Out of Scope

- 日志压缩、按大小二次切分、远程日志收集、管理页在线查看或下载日志。
- 改变监控、迁移数据、通知、Bot 或 Cookie 续期逻辑。
- 改变独立 PG 迁移工具的文件输出策略；其 stderr 继续使用原有文本日志。
- 自动修改用户现有部署配置或启动现有业务服务。

## Acceptance Criteria

- [x] 默认路径、自定义路径、环境变量覆盖及相对路径解析正确，管理页/API 可查看实际日志目录。
- [x] 普通日志同时出现在终端和普通文件；成功/警告 SQL 只在 SQL 文件；失败 SQL 在 SQL 文件和终端均可定位。
- [x] 文件日志保留调用链、完整错误堆栈和脱敏；SQL 使用占位符，后台只读轮询仍静默。
- [x] 按配置时区跨午夜切分，两类日志同日重启均追加；并发日志没有丢失或交错。
- [x] 精确保留 30 个自然日，只清理过期的本服务日志，不误删其他文件。
- [x] 不可用日志路径导致明确启动失败；正常退出释放日志文件，写入失败不会被静默忽略。
- [x] 使用临时数据和假凭据完成实际服务启动、HTTP 请求和停止核验；Go 构建、vet、相关测试及文档检查通过。
