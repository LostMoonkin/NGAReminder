# Spec16：按时段导出内容

## 目标

现有 TID/UID 导出只能下载全部已保存内容，内容积累较多时无法只保留某个时间段内的帖子；管理页同时展示 Markdown 和 ZIP 两个独立按钮，也无法在一次操作中同时选择范围与格式。

完成后，用户可以从原有 TID/UID 内容页选择全量或指定时间段，并导出 Markdown 或 ZIP。API 调用方也可以用精确到秒、包含边界的可选时间参数限制导出内容。

## 行为

- TID 和 UID 的 Markdown、ZIP 导出接口新增可选查询参数 `start_at`、`end_at`，按帖子的发布时间 `published_at` 筛选。
- `start_at` 表示最早发布时间，`end_at` 表示最晚发布时间；两个边界都包含在结果中，精确到秒。
- 两个参数都可省略；全部省略时保持现有全量导出行为。只提供一个参数时执行单边筛选。
- API 接受带时区的 RFC 3339 秒级时间；管理页提交的 `datetime-local` 值按服务配置的 `timezone` 解释，浏览器省略 `:00` 秒时视为该分钟的第 0 秒。时间统一转换后再与数据库中的 UTC 时间比较。
- 指定任一时间边界后，发布时间未知的内容不进入导出结果。UID 导出仍只包含目标 UID，TID 导出仍只包含目标主题，不因筛选或导出额外抓取内容。
- 开始时间晚于结束时间、时间格式无效或包含秒以下精度时返回可理解的参数错误，不生成导出文件。筛选后无内容时沿用现有“没有可导出的已保存内容”反馈。
- 管理页将原有两个导出按钮整合为一个“导出内容”入口。点击后显示悬浮窗，并在同一表单中选择：
  - 导出范围：全量导出或指定时间段；
  - 导出格式：Markdown 或 ZIP。
- 选择指定时间段时必须填写开始和结束时间，输入控件支持秒；界面明确提示首尾均包含，并显示采用的配置时区。
- 悬浮窗提交后仍使用现有下载响应。关闭或取消悬浮窗不发起请求；禁用 JavaScript 时仍提供可提交的基础导出表单。
- 时间筛选不改变 Markdown 渲染、ZIP 资源处理、内容顺序、快照边界、临时文件清理和下载文件命名规则。

## 约束

- 复用现有 `/admin/exports/:kind/:id` 与 `/api/v1/exports/:kind/:id` 路由及 `format=markdown|zip` 参数，不新增导出任务或新的下载路由。
- 只查询 SQLite 中已经保存的内容，继续遵守 [阶段 07](07-content-and-export.md) 和 [Markdown 渲染 Spec13](13-markdown-rendering.md) 的导出与资源规则。
- 管理页沿用 [管理台 UI Spec15](15-admin-ui.md) 的原生模板、CSS 和 JavaScript，不引入前端依赖或独立构建流程。
- 仅修改 Go 服务端和其管理页；独立 Chromium 扩展的存储、界面与发布流程不变。

## 非目标

- 不给内容浏览列表增加时间筛选，也不改变分页结果。
- 不按采集时间、入库时间或监控运行时间筛选。
- 不增加预设日期范围、导出历史、后台异步导出或计划导出。
- 不补抓缺失正文、缺失发布时间或资源。

## 验收标准

- [x] TID 与 UID 的 Markdown、ZIP API 在省略时间参数时保持原有全量结果。
- [x] 使用起止时间导出时，只包含 `published_at` 位于闭区间内的帖子；首秒、尾秒均被包含，区间外及未知发布时间内容被排除。
- [x] 只传开始或结束时间可完成单边筛选；RFC 3339 时区换算及管理页配置时区输入得到相同的秒级边界结果。
- [x] 无效时间、秒以下精度和倒置区间返回 400；筛选为空时返回现有无内容提示，且不遗留临时文件。
- [x] TID/UID 内容页只显示一个主要导出入口；悬浮窗可选择全量/时间段及 Markdown/ZIP，时间段输入包含秒并显示配置时区与闭区间提示。
- [x] 禁用 JavaScript 后仍能提交全量或时间段导出；桌面与手机宽度下悬浮窗和基础表单可用。
- [x] 相关 Go 测试、`CGO_ENABLED=0 go build ./...`、`CGO_ENABLED=0 go vet ./...`、`CGO_ENABLED=0 go test ./...`、JavaScript 语法检查和 `git diff --check` 通过。
