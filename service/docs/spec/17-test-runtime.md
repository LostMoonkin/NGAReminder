# 服务端全量测试提速

## Goal

当前服务端主 Go module 的全量测试耗时约 147 秒，主要时间消耗在测试进程真实等待 NGA 请求限流、查询重试和后台 ticker，与项目体量不匹配，也降低了本地修改和 CI 验证的反馈速度。

完成后，开发者可以在不改变生产运行行为和现有业务断言的前提下，于 30 秒内完成一次禁用测试结果缓存的服务端全量测试。

## Behavior

- `service/` 主 Go module 的现有测试继续验证相同的业务流程、错误处理、并发规则和持久化结果。
- NGA fixture 的限流与重试不再消耗生产配置对应的真实墙钟时间；空闲轮询与并发 fixture 不再依赖多秒固定等待。
- 并发测试必须根据可观察到的请求进入、释放和完成事件判断结果，不能依赖足够长的固定等待来猜测并发已经发生。
- CI 每次实际执行测试，不使用 Go 测试结果缓存掩盖耗时回归，并为单个测试 package 设置 30 秒超时。

## Constraints

- 生产环境的 NGA 120 QPM 限流、用户查询重试次数与间隔、调度周期和 Bot 连接周期保持不变。
- 测试继续使用本地 fixture、临时 SQLite 和现有分层，不访问真实 NGA、飞书或 Bark。
- 保持 `CGO_ENABLED=0`，不新增外部测试服务或常驻测试进程。
- 优化后的测试必须保持确定性，不能通过跳过业务断言、减少业务场景或依赖测试并行来满足耗时目标。

## Out of Scope

- 不调整生产抓取、重试、通知或调度策略。
- 不重构业务分层、数据库结构或管理页。
- 不为本轮增加测试覆盖率目标。
- 不优化独立的 `tools/pg-migrate` module；其测试不属于当前 CI 的主 module 全量命令。

## Acceptance Criteria

- 在构建缓存已准备完成的同一环境中，连续三次执行 `CGO_ENABLED=0 go test -count=1 -timeout=30s ./...` 均通过，且每次墙钟耗时不超过 30 秒。
- NGA 120 QPM 限流测试仍验证连续请求的虚拟时间间隔不少于 500ms，并在不等待真实一分钟的情况下通过。
- 503/业务繁忙重试、空闲后台轮询、并发页面抓取和 Bot 连接失败场景继续通过原有结果断言。
- `CGO_ENABLED=0 go build ./...`、`CGO_ENABLED=0 go vet ./...` 和 `git diff --check` 通过。
- CI 的服务端测试命令禁用测试结果缓存并设置 30 秒 package 超时。
