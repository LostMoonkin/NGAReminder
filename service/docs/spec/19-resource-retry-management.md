# 资源维护展示与缺失资源管理

## Goal

资源维护页目前直接显示原始字节数，较难快速判断容量；缺失资源全部平铺并在补下载时整批重试，无法区分已确认 404 的资源，也无法忽略不再需要处理的项目。

完成后，管理员可以直接阅读容量数据，展开缺失列表后选择性补下载或忽略资源，并只在汇总中看到已确认 404 和已忽略的数量。

## Behavior

- 资源维护页上的单资源上限、SQLite 占用、assets 占用及文件明细大小使用 B、KiB、MiB、GiB 等可读单位，不再只显示原始字节数。
- 资源下载收到 HTTP 404 时持久化记录状态；已记录 404 的缺失资源不再自动或手动重试。
- 已记录 404 的资源不出现在可操作的缺失资源列表中，页面和 GET API 只返回其数量汇总。
- 可操作的缺失资源列表默认收起，可由管理员展开；每项提供选择框，并提供全选和反选。
- 重新下载只处理当次提交且仍属于可操作缺失列表的资源；未选中、已忽略、已记录 404 或已不再缺失的资源不下载。
- 管理员可忽略当次选中的缺失资源。已忽略状态持久化，资源不再自动或手动下载，不出现在可操作列表中，页面和 GET API 只返回其数量汇总。
- 没有选择资源时，重新下载和忽略请求都返回明确的输入错误，不修改资源记录。

## Constraints

- 继续使用现有资源维护页、GET API 与表单提交方式；管理 API 仍使用 Bearer token。
- 可读容量只改变管理页展示，API 的字节字段继续返回原始整数值。
- 补下载和忽略只能作用于当前已保存正文引用的资源，不接受任意外部 URL。
- 保持资源下载的现有域名、跳转、类型和大小限制；单个下载失败不中断其他已选资源。

## Out of Scope

- 恢复已忽略资源、重置 404 状态或定时重试 404。
- 展示已忽略或 404 资源的 URL 明细。
- 修改已有原始字节 API 字段的单位或类型。

## Acceptance Criteria

- 资源维护页不再以裸整数字节值展示单资源上限、SQLite、assets 和文件明细大小；容量跨 B、KiB、MiB、GiB 时格式正确。
- 一个被引用资源首次返回 404 后记录 HTTP 状态，后续扫描只增加 404 计数，不再列出或发起下载。
- 缺失列表可展开和收起，全选与反选只改变该列表的选中状态。
- 从至少两个可操作缺失资源中选择一项重新下载时，只向所选资源发起请求。
- 忽略所选资源后，状态在服务重启后仍保留，扫描只增加忽略计数，不再列出或下载。
- 表单与 API 均拒绝空选择和不属于当前可操作缺失列表的 URL。
- 已有资源扫描、清理、导出与统计行为保持通过；`CGO_ENABLED=0 go build ./...`、`CGO_ENABLED=0 go vet ./...`、`CGO_ENABLED=0 go test -count=1 -timeout=30s ./...` 和 `git diff --check` 通过。
