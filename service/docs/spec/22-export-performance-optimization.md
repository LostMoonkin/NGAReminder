# Spec22：大规模内容导出性能优化

## Goal

当前保存超过 12 万楼的主题在全量导出时耗时超过 20 分钟仍未完成。主要原因是导出过程对帖子排序与分页存在 $O(N^2)$ 重复全量读取排序、对每条引用目标执行无索引逐条查库、对 ZIP 资源逐条重复查库与打开目录并对已压缩媒体重复 Deflate 压缩。

完成后，大规模主题/用户内容的同步与异步导出（Markdown 与 ZIP）在保持输出结果完全一致的前提下，消除导出链路中的 $O(N^2)$ 扫描与逐条 N+1 查询，将 12 万条级别主题导出耗时降至数十秒内，且导出期间不长时间阻塞其他并发请求对 SQLite 的访问。

## Behavior

- 导出流程按线性复杂度完成数据读取、排序、引用解析与文件写出，不再按深度 `OFFSET` 重复全量排序或逐条引用查询数据库。
- 导出仅读取导出所需的帖子字段，不加载导出未使用的原始 JSON 字段（`raw_payload`）。
- 导出在保持与既有实现完全一致的排序规则（TID、楼层/父楼层、评论顺序与内部 ID）、快照边界、时间段筛选、作者 UID 过滤及引用链接语义的前提下生成 Markdown 与 ZIP。
- 文内引用判定在单次导出内复用全量快照范围的引用索引，跨批次引用同一目标不再重复查库；不在导出范围内的引用仍回退为 NGA 原帖链接。
- ZIP 导出避免对同一资源 URL 或本地文件反复查库与重复打开目录句柄；对已压缩格式的媒体/归档资源（如常见图片、音视频、压缩包等）采用仅归档（Store）写入，文本类条目（`content.md`、`metadata.json`）继续压缩。
- 导出文件写出采用内存缓冲，减少细粒度磁盘写入系统调用。
- 导出分批读取正文时在批次间释放 SQLite 连接，避免大导出期间长时间阻塞健康检查、管理页刷新或监控采集。
- 提供可复现的导出性能基准测试，用于验证大帖子（含跨楼层引用与本地资源）导出耗时与结果一致性。

## Constraints

- 保持既有 Markdown 渲染（[Spec13](13-markdown-rendering.md)）、时段筛选（[Spec16](16-time-ranged-content-export.md)）、异步导出（[Spec20](20-async-content-export.md)）和 UID 过滤（[Spec21](21-thread-export-uid-filter.md)）的外部接口与输出语义不变。
- 保持单机单进程、SQLite（`CGO_ENABLED=0`）与有限内存占用，不将全部帖子正文或全部资源二进制同时载入内存。
- 继续遵守资源目录的路径防越界与禁止跟随符号链接安全约束。
- 常规全量测试继续遵守 [Spec17](17-test-runtime.md) 的 30 秒预算；大规模性能基准通过 Go benchmark 按需执行，不拖慢常规 `go test ./...`。
- 仅修改 Go 服务端，不改动管理页交互结构或独立 Chromium 扩展。

## Out of Scope

- 修改数据库引擎、引入外部缓存服务或更改 SQLite 单连接写入模型。
- 改变 Markdown 排版格式、锚点命名、ZIP 目录结构或 `metadata.json` 字段语义。
- 为导出增加多文件分卷、增量差分导出或断点续导。

## Acceptance Criteria

- 同一数据集下，优化前后导出的 Markdown 内容、顺序、引用锚点/原帖回退链接以及 ZIP 条目内容与 `metadata.json` 语义完全一致（覆盖 TID/UID、时段筛选与 UID 过滤）。
- 导出查询不再触发每条引用一次数据库查询或每批全量 `OFFSET` 排序；导出过程中保持合理内存占用（仅分批载入正文、逐个流式拷贝资源）。
- ZIP 导出中已压缩媒体资源以 Store 方式写入且可正常解压校验，文本条目保持压缩，缺失资源与符号链接防护行为不变。
- 导出期间并发访问 `/readyz` 或管理页查询不会被整段导出全程阻塞。
- 新增 Go 性能基准测试可对大规模帖子（含引用与资源）直接测量 Markdown 与 ZIP 导出耗时，12 万条主题导出在本地基准中可在数十秒内完成。
- `CGO_ENABLED=0 go build ./...`、`CGO_ENABLED=0 go vet ./...`、`CGO_ENABLED=0 go test -count=1 -timeout=30s ./...` 和 `git diff --check` 通过。
